# 판정 화면으로 이어지는 수는 판정 목록의 줄 수다

- 날짜: 2026-11-25
- 상태: 확정

## 배경

판정 목록은 비밀 값 묶음을 한 줄씩, 고객정보는 같은 파일, 종류, 판정의 묶음을 모아 한 줄로 보인다. 그런데 상태 탭의 수(`VerdictCounts`, `Entries`의 `Counts`)는 묶음 수였다. 그래서 고객정보 한 줄이 탭에서는 2 이상으로 셀 수 있었고, 탭의 수와 그 탭을 눌렀을 때 보이는 줄 수가 달랐다.

같은 묶음 수를 여러 화면이 쓴다.

- 판정 화면: 상태 탭, 머리말 "미판정 N / 전체 M"
- 스캔 화면과 프로젝트 화면: "판정하기 · 미판정 N" 버튼, 판정 타일
- 프로젝트 목록: "미판정", "전체"
- 대시보드: "남은 항목", "미판정 · 보류 · 적용 대기", 완료율(0045)
- 리포트 요약(0042)

## 결정

- 판정 화면으로 이어지는 수는 모두 판정 목록의 줄 수로 센다. 판정 화면의 상태 탭과 머리말, 스캔·프로젝트 화면의 버튼과 타일(`VerdictCounts`), 프로젝트 목록(`ProjectSummaries`)이 해당된다. 세는 방법은 목록을 만드는 `entry`와 같다.
- 대시보드와 리포트는 묶음 수로 둔다.
- 사용자가 #114의 선택지 가운데 추천안(2번)을 골랐다.

## 이유

- 판정 화면으로 이어지는 숫자는 그 화면에서 처리할 일의 양이다. 고객정보는 한 줄을 한 번에 판정하므로 줄 수가 일의 양이다. 이제 탭의 수, 탭을 눌렀을 때의 줄 수, 다른 화면의 "미판정 N"이 모두 같다.
- 대시보드와 리포트는 남은 값의 추이와 완료율을 보는 곳이라 값(묶음)의 수가 맞다. 줄 수로 바꾸면 고객정보가 많은 프로젝트의 남은 항목과 완료율이 크게 바뀌고, 이전 리포트 PDF와도 맞지 않는다.

## 검토한 다른 방법

- 판정 화면의 탭만 줄 수로 세기: 탭과 목록은 맞지만, 머리말과 스캔 화면의 "미판정 N"이 판정 화면과 달라진다.
- 대시보드까지 모두 줄 수로 세기: 수는 어디서나 같지만, 남은 항목과 완료율의 뜻이 바뀐다.
- 그대로 두고 "고객정보는 묶음 수" 안내만 붙이기: 수가 어긋나는 문제는 남는다.
- 한계: 대시보드의 "미판정"(묶음 수)과 프로젝트 목록의 "미판정"(줄 수)은 고객정보가 한 파일에 여럿 있으면 다르다.
