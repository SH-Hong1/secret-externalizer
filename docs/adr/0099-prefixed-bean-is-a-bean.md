# 이름공간 접두사가 붙은 bean도 설정 키의 bean으로 본다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

0053은 값의 자리에서 열려 있는 가장 가까운 `<bean …>`의 `id`를 키 앞에 붙이고, `<beans:bean>`처럼 접두사가 붙은 요소는 bean으로 보지 않았다. Spring Security 설정처럼 기본 이름공간이 `beans`가 아닌 파일은 bean을 `<beans:bean id="ds">`로 쓴다. 그런 파일에서는 bean마다 다른 데이터 소스의 비밀번호가 모두 `password`를 받아 나뉘지 않았다(이슈 #61의 일부).

## 결정

1. **열린 bean을 찾을 때, 요소 이름이 `bean`이면 접두사(`글자:`)가 있든 없든 bean으로 본다**(`isBeanTag`). 닫는 태그(`</beans:bean>`)도 같다.
2. 이름이 정확히 `bean`인 요소만 bean이다. `<beans:beans>`(루트)나 `<x:beanx>`는 bean이 아니다.
3. 접두사가 무엇인지는 보지 않는다. 이름공간 선언(`xmlns:beans="…"`)을 따라가지 않는다.

## 이유

- 접두사는 같은 Spring bean 요소를 다른 기본 이름공간 아래에서 쓰기 위한 것일 뿐이어서, 접두사가 없는 bean과 같은 규칙을 받는 것이 맞다.
- 이름공간 선언을 따라가려면 파일 앞부분을 파싱해야 한다. 0053의 글자 수준 읽기를 지키고, `bean`이라는 이름의 다른 요소를 bean으로 잘못 보는 위험은 키가 덜 정확해질 뿐 값을 드러내지 않는다.

## 검토한 다른 방법

- **`beans:` 접두사만 받는다.** 흔한 접두사지만 이름은 파일마다 정할 수 있다(`b:bean`, `spring:bean`). 접두사 이름에 기대는 규칙은 깨지기 쉽다.

## 알려진 한계

- 키가 바뀐 자리(접두사가 붙은 bean 안의 값)는 다음 스캔에서 새 항목이 되어 전의 판정을 이어받지 않는다(이슈 #56).
- 같은 파일의 두 Tomcat `Resource`가 같은 키 `password`를 받아 나뉘지 않는 문제는 0100에서 다룬다.
