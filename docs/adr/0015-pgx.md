# postgres 클라이언트에 pgx를 쓴다

- 날짜: 2026-11-19
- 상태: 확정

## 배경

프로젝트, 스캔 결과, 작업 큐를 postgres에 저장한다. 표준 라이브러리의 `database/sql`에는 postgres 드라이버가 없으므로 의존성 추가의 이유를 기록한다.

## 결정

`github.com/jackc/pgx/v5`를 쓰고, 연결 풀은 `pgxpool`을 쓴다. `database/sql` 어댑터(`stdlib`)는 쓰지 않는다.

## 이유

- 큐가 쓰는 `FOR UPDATE SKIP LOCKED`, `pg_advisory_lock`, `text[]` 열을 드라이버가 그대로 지원한다. `text[]`는 `[]string`으로 바로 읽고 쓴다.
- `pgxpool`이 풀, 연결 상태 확인, 연결 수명을 갖추고 있어 직접 만들 것이 없다.
- 모든 호출이 `context.Context`를 첫 인자로 받아 `AGENTS.md`의 규칙과 맞는다.
- 연결 문자열을 URL과 키-값 두 형식으로 읽는다. 연결 오류는 호스트와 사용자만 담고 비밀번호는 담지 않는다. 그래도 `db.Open`은 URL 해석 오류를 버리고 고정 문장을 돌려준다. 해석 오류가 입력의 일부를 인용할 수 있기 때문이다.
- postgres 드라이버로 가장 널리 쓰이고 `lib/pq`는 유지보수 모드다.

## 검토한 다른 방법

- `database/sql`과 `lib/pq`: `lib/pq`는 새 기능을 더하지 않고, 배열과 풀 설정을 다루기에 불편하다.
- `database/sql`과 `pgx/stdlib`: 표준 인터페이스를 얻지만 `pgx`의 배열, 일괄 전송, 알림 같은 기능을 쓰기 어렵다. 이 프로젝트는 드라이버를 바꿀 계획이 없다.
- `sqlc` 같은 코드 생성: 질의가 적은 지금은 도구를 더할 이유가 없다. 질의가 늘면 새 결정으로 다시 검토한다.
