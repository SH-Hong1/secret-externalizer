# betterleaks에 스캔마다 제외 경로를 담은 규칙 파일을 넘긴다

- 날짜: 2026-11-25
- 상태: 확정

## 배경

0087은 프로젝트별 제외 경로를 스캔마다 스캐너에 넘기기로 했지만, betterleaks에는 경로를 제외하는 실행 옵션이 없어 받은 제외 경로를 쓰지 않았다. betterleaks는 제외한 폴더(내려받은 라이브러리, 산출물 사본)도 모두 읽었고, 스캔 실행기가 그 결과를 버렸다.

betterleaks 1.10.1은 규칙 파일의 `[extend] path`로 다른 규칙 파일을 잇고, 전체에 걸리는 `[[allowlists]] paths`의 정규식에 맞는 폴더로는 내려가지 않고 맞는 파일은 읽지 않는다. 정규식은 스캔한 폴더 기준의 상대 경로(`vendor/lib`)에 맞춘다. 이은 규칙 파일의 `[extend] useDefault = true`도 그대로 걸려 기본 규칙이 남는 것을 실제 실행으로 확인했다.

## 결정

- 제외 경로가 있는 스캔은 스캐너의 임시 폴더(`<SCAN_TEMP_DIR>/tmp`)에 규칙 파일 하나를 만들어 `--config`로 넘긴다. 이 파일은 `[extend] path`로 설정된 규칙 파일(절대 경로)을 잇고, `[[allowlists]] paths`에 제외 경로마다 정규식 `^<경로>(?:/|$)`를 둔다. 경로는 `regexp.QuoteMeta`로 이스케이프하고, TOML 기본 문자열로 쓴다.
- 이 파일은 스캔이 끝나면 지운다. worker가 강제로 죽어 남은 파일은 0089의 정리가 지운다.
- 제외 경로가 없는 스캔은 지금처럼 설정된 규칙 파일을 그대로 넘긴다.
- 스캔 실행기가 파일 목록에 없는 파일의 결과를 버리는 규칙(0021)은 그대로 둔다.

## 이유

- `[extend]`로 원래 규칙 파일을 이으면 규칙을 다시 쓰지 않고 제외 경로만 더할 수 있다. 규칙 파일은 worker 전체에서 하나로 남는다.
- `(?:/|$)`로 끝을 막아 `skip`이 `skipped/`를 제외하지 않고, 제외한 폴더 자체에서 걷기를 멈춘다. `^vendor/`처럼 쓰면 `vendor` 폴더 안으로는 내려가고 그 안의 항목마다 건너뛴다.
- 임시 폴더는 스캐너의 `TMPDIR`과 같은 곳이라, 스캔이 남긴 다른 임시 파일과 같은 정리 규칙을 따른다.

## 검토한 다른 방법

- 규칙 파일 내용을 환경 변수 `BETTERLEAKS_CONFIG_TOML`로 넘기기: 파일을 쓰지 않아도 되지만, 제외 경로 수에 따라 한 환경 변수의 크기 한도(Linux에서 128KiB)에 걸릴 수 있고 `--config`보다 우선순위가 낮아 인자를 바꿔야 한다.
- 제외하지 않은 최상위 항목만 경로 인자로 넘기기: 0087에서 본 대로 깊은 제외 경로를 다루기 어렵다.
