# 같은 값의 묶음은 묶음 단위로 한 번에 합친다

- 날짜: 2026-11-24
- 상태: 확정

## 배경

0053은 한 파일의 같은 값을 설정 키마다 나누고, 실제로 같은 비밀인 자리(`jdbc.password`, `jdbc.slave.password`)는 사람이 합치게 했다. 합치는 방법은 항목을 하나씩 다른 묶음으로 옮기는 것뿐이었다. 항목이 여럿인 묶음은 항목 수만큼 눌러야 했고, 중간에 한 항목이 거부되면 일부만 옮겨진 채 남았다. 같은 값의 묶음이 더 있다는 것도 옮기기 양식을 열어 봐야 알 수 있었다.

## 결정

1. 묶음 상세에 "이 묶음 전체 합치기" 양식을 둔다. 같은 값의 다른 묶음이 있을 때만 보이고, 점검이나 적용 중에는 보이지 않는다. 같은 값의 묶음이 몇 개 더 있는지와, 환경마다 값을 따로 바꿔야 하면 합치지 말라는 안내를 함께 보인다.
2. `db.Store.MergeBundle(from, to)`는 `from`에 저장된 모든 항목(마지막 스캔이 찾지 못한 항목도)을 한 트랜잭션에서 `to`로 옮긴다. 항목마다 `MoveFinding`과 같은 규칙(`moveFinding`)을 적용하므로 하나라도 거부되면 아무것도 옮기지 않는다. `from`은 비어서 지워지고 이름이 풀린다.
3. 감사 기록은 `MoveFinding`과 같이 옮긴 항목마다 `move` 하나를 남긴다. 합치기를 따로 구별하는 행위 이름은 만들지 않는다.
4. 같은 값인지, 합쳐도 되는지는 자동으로 판단하지 않는다. 사람이 정한다.

## 이유

- 키가 다른 같은 값이 실제로 같은 비밀인지는 이름만으로 알 수 없다. `local.db.password`와 `dev.db.password`는 값이 같아도 따로 바꿔야 하고 `jdbc.password`와 `jdbc.slave.password`는 한 비밀이다. 0053이 자동으로 나누기를 고른 이유가 그대로 유효하므로 자동 합치기는 하지 않는다.
- 규칙을 한 곳에 두려고 `MoveFinding`의 본문을 `moveFinding`으로 떼어 `MergeBundle`이 되풀이해 부른다. 옮기기의 거부 조건(적용한 위치, 적용한 묶음의 마지막 항목, 고객정보, 다른 지문, 판정이 받아들이지 않음)이 합치기에도 똑같이 적용된다.
- 한 트랜잭션이어야 하는 것은 일부만 옮겨진 묶음이 남지 않게 하기 위해서다.

## 검토한 다른 방법

- 같은 값과 비슷한 키(`jdbc.*`)를 보고 자동으로 합친다: 위 이유로 버렸다.
- 웹이 `MoveFinding`을 항목마다 부른다: 거부되면 일부만 옮겨진다.
- 합치기 전용 감사 행위를 만든다: 읽는 쪽(감사 화면, 리포트의 판정 이력)을 함께 바꿔야 하고, 옮긴 항목마다의 기록으로 충분하다.

## 알려진 한계

- 항목이 많은 묶음은 항목마다 쿼리를 보내는 한 트랜잭션이다. 한 묶음의 항목은 보통 수십 개 이하다.
- 합친 뒤에 되돌리는 것은 항목을 하나씩 "따로 떼기"로 한다.
