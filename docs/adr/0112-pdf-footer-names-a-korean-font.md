# PDF 바닥글은 변환기 이미지의 한글 글꼴을 이름으로 쓴다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

PDF 바닥글은 `secret-externalizer | scan #N | 쪽 / 전체`였고 ASCII만 썼다(0044). 바닥글은 본문과 따로 그려져 함께 보낸 글꼴을 쓰지 못하므로 한글이 그려지지 않을 것이라고 보았기 때문이다. 그래서 프로젝트 이름이 바닥글에 없었다. 또 `body`에 건 `text-align: right`가 먹지 않아 바닥글이 왼쪽에 붙었다(#76).

실제 변환기(Gotenberg 9.9.1-chromium)로 확인한 것:

- 이미지에는 Noto Sans CJK(KR, JP, SC, TC, HK)가 설치되어 있다. 바닥글의 한글은 보낸 글꼴 없이도 그려진다.
- 글꼴 이름을 주지 않으면 바닥글의 한글과 한자는 `NotoSansCJKjp`로 그려진다. 바닥글의 `<html lang="ko">`는 대체 글꼴 선택에 쓰이지 않는다. `font-family: "Noto Sans CJK KR"`를 주면 `NotoSansCJKkr`로 그려진다.
- `body`의 `text-align: right`는 글을 옮기지 않는다. 너비 100%인 `div` 안에서는 오른쪽 정렬이 된다.

## 결정

- 바닥글은 `secret-externalizer | 프로젝트 이름 | scan #N | 쪽 / 전체`이다. 프로젝트 이름은 `html/template`이 이스케이프한다.
- 바닥글의 글꼴은 `"Noto Sans CJK KR", sans-serif`이다.
- 바닥글은 너비 100%인 flex 줄에 `justify-content: flex-end`로 오른쪽에 붙인다. 프로젝트 이름(100자까지)이 한 줄에 들어가지 않으면 이름만 줄임표로 자르고, 앞뒤의 도구 이름, 스캔 번호, 쪽 번호는 자르지 않는다.
- `internal/pdf`의 실제 변환기 테스트가 한글 바닥글의 PDF에 `NotoSansCJKkr`가 들어가는지 본다.

## 이유

- 여러 프로젝트의 PDF를 인쇄해 섞으면 쪽만 보고 어느 프로젝트의 것인지 알 수 있어야 한다. 프로젝트 이름은 본문 첫머리에만 있었다.
- 한국어 이름의 한자는 일본어 글꼴로 그리면 모양이 다르다. 글꼴 이름을 주면 이미지에 있는 KR 글꼴로 정해진다. 글꼴이 이미지에서 빠지면 `sans-serif`로 돌아가고, 테스트가 그것을 알린다.
- 줄임표로 자르면 바닥글이 언제나 한 줄이라 여백(0.8in) 안에 들어간다. 쪽 번호는 잘리면 안 된다.

## 검토한 다른 방법

- **바닥글에 보낸 글꼴(IBM Plex Sans KR)을 data URL로 넣는다.** 바닥글은 파일을 읽지 않지만 data URL은 읽을 수 있을지 모른다. 글꼴 하나가 수백 KB라 요청이 커지고, 이미지에 이미 한글 글꼴이 있다.
- **ASCII만 쓰고 프로젝트 ID를 적는다.** 사람이 읽는 것은 이름이다.
- **긴 이름을 두 줄로 감싼다.** 바닥글 높이가 이름에 따라 달라지고 여백을 넘을 수 있다.
