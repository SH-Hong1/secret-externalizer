# `://`가 없는 jdbc URL과 XML 속성 값 안의 `>`에서 설정 키를 바로 읽는다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

0053의 "알려진 한계"에 두 경우가 있었다(이슈 #62).

1. 규칙이 구성 요소로 나누지 않은 Oracle thin URL(`db.url=jdbc:oracle:thin:shopadmin/비밀번호@db:1521/shop`)에서 직접 규칙이 찾은 계정의 키는 `thin`이었다(`thin:`을 `:` 대입으로 읽었다). 비밀번호의 키는 비어 있었다(앞 글자가 `/`여서 대입을 찾지 못했다). 키를 URL의 앞에서 읽는 규칙(`urlStart`)이 `scheme://` 모양만 알아보았기 때문이다.
2. 바깥 bean 안의 자기 닫힘 bean이 속성 값 안에 `>`를 가지면(`<bean id="i" init="a>b"/>`) 그 `>`에서 태그가 끝난 것으로 보아 자기 닫힘을 알아보지 못했다. 그래서 그 bean을 열린 bean으로 세어, 뒤쪽 `<property name="password" …/>`의 키가 `outer.password`가 아니라 `i.password`였다.

## 결정

1. **`://`가 없어도 `jdbc:`로 시작하는 글자열 안의 값은 그 글자열의 시작에서 키를 읽는다.** `urlStart`가 먼저 `scheme://`를 찾고, 없으면 같은 줄에서 값 앞의 마지막 `jdbc:`(대소문자 무시, 앞 글자가 영문자나 숫자가 아닐 것)를 찾는다. `jdbc:`와 값 사이에 공백, 따옴표, `<`, `>`가 있으면 쓰지 않는다. 위 예의 계정과 비밀번호는 모두 `db.url`을 받는다.
2. **bean 태그의 끝을 찾을 때 따옴표 안의 `>`는 건너뛴다**(`tagClose`). 속성 값 안의 `>`는 XML에서 허용되므로 실제 파일에 나올 수 있다.

## 이유

- 0053 결정 2는 URL 안의 값이 URL의 키를 받게 하려는 것이었다. Oracle thin 모양은 `://`가 없을 뿐 같은 경우다. `jdbc:`는 JDBC URL의 정해진 머리이므로 다른 설정을 URL로 잘못 볼 일이 적다.
- 따옴표를 따라가는 것은 태그 안에서만이다. bean 태그는 `<bean`에서 시작하므로 그 뒤의 따옴표는 속성 값의 따옴표다.
- 두 경우 모두 키에 값이 들어가지 않는 것은 전과 같다. 키를 읽은 범위가 가리는 범위와 겹치면 비우는 규칙(0053 결정 3)도 그대로다.

## 검토한 다른 방법

- **Oracle thin URL을 구성 요소로 나누는 규칙을 더한다.** 계정, 비밀번호, 호스트가 한 묶음의 구성 요소가 되어 더 낫지만, 규칙과 나누기(0026)를 함께 바꾸는 더 큰 일이다. 키만 맞추는 이 결정과 겹치지 않는다.
- **XML을 파서로 읽는다.** 주석, 여러 줄 태그 같은 다른 한계도 풀리지만, 깨진 XML과 템플릿 문법이 섞인 파일에서 키를 아예 읽지 못하게 된다. 글자 수준으로 읽는 0053의 방식을 지킨다.

## 알려진 한계

- 키가 바뀐 자리(Oracle thin URL의 계정과 비밀번호, 속성 값 안에 `>`가 있는 자기 닫힘 bean 뒤의 값)는 다음 스캔에서 새 항목이 되어 전의 판정을 이어받지 않는다(이슈 #56).
- 따옴표가 짝이 맞지 않는 깨진 bean 태그는 파일 끝까지 열려 있는 것으로 본다. 키가 덜 정확할 뿐 값을 드러내지는 않는다.
- 속성 값 안의 `<`는 여전히 태그의 시작으로 볼 수 있다(`openBean`은 `<`를 거꾸로 찾는다).
