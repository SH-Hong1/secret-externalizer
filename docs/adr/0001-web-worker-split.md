# web과 worker를 별도 프로세스로 나눈다

- 날짜: 2026-11-18
- 상태: 확정

## 배경

이 도구는 로그인 화면을 제공하면서, 동시에 소스 파일을 고치고 스캐너를 실행하고 OpenBao에 원본 값을 쓴다. 이 권한들이 한 프로세스에 모이면 웹 쪽 취약점 하나로 전부 노출된다.

## 결정

하나의 Go 모듈에서 `cmd/web`과 `cmd/worker` 두 바이너리를 만들어 컨테이너를 나눈다. 둘은 postgres의 작업 큐로만 연결한다.

- web: HTTP 서버, 화면, 판정 기록, 작업 요청. 소스 마운트와 스캐너가 없다. OpenBao는 읽기만 한다.
- worker: 스캔, 적용, 재스캔. 포트를 열지 않는다. OpenBao에 쓰고 지운다.

## 이유

- 민감 정보를 다루는 도구이므로 권한 분리의 이점이 컨테이너 하나의 비용보다 크다.
- 스캔이 오래 걸려도 화면이 멈추지 않는다.
- `cmd/` 아래 두 바이너리가 `internal/`을 공유하는 구조는 Go 서버 프로젝트의 표준 배치다.

## 검토한 다른 방법

- 단일 프로세스: 구성이 가장 단순하지만 위의 권한 집중 문제가 있다.
- docker client로 스캐너 컨테이너를 매번 실행: 0002 참조.
