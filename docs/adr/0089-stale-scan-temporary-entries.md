# 끝난 스캔이 남긴 사본과 임시 파일을 다음 스캔이 지운다

- 날짜: 2026-11-25
- 상태: 확정

## 배경

스캔은 EUC-KR 파일의 UTF-8 사본을 `<SCAN_TEMP_DIR>/copies/<스캔 ID>/`에 두고, 스캔이 끝날 때 `defer`로 지운다(0021, 0023). worker가 강제로 죽으면(`kill -9`, 호스트 종료) 이 정리가 돌지 않는다. 같은 스캔이 다시 시도되면 사본 폴더를 비우고 시작하지만, 그 스캔이 임대 만료 뒤 실패로 끝나 다시 돌지 않으면 사본은 그대로 남는다. 사본은 스캔 대상 파일의 내용이므로 "스캔이 끝나면 지운다"는 규칙(AGENTS.md Security)을 어긴다. compose에서는 이 폴더가 tmpfs라 컨테이너가 다시 만들어질 때 사라지지만, 컨테이너 밖에서 worker를 돌리면 남는다. 스캐너의 임시 폴더(`<SCAN_TEMP_DIR>/tmp`, 스캐너의 `TMPDIR`)도 같다.

여러 worker가 같은 `SCAN_TEMP_DIR`을 쓸 수 있으므로, worker가 시작할 때 폴더를 통째로 비우면 다른 worker가 진행 중인 스캔의 사본을 지울 수 있다.

## 결정

- 스캔은 시작할 때(`Handle`의 처음) 사본 폴더와 스캐너의 임시 폴더에서, 마지막으로 바뀐 시각이 지금보다 스캔 시간 한도(`TimeLimit`)의 두 배 넘게 앞선 항목을 지운다. 항목이 심볼릭 링크이면 링크만 지운다.
- 목록을 읽지 못하거나 지우지 못하면 경고 로그를 남기고 스캔은 계속한다.
- 스캐너의 `HOME`(`<SCAN_TEMP_DIR>/home`)은 지우지 않는다.

## 이유

- 스캔 하나는 시간 한도를 넘기면 취소된다. 그래서 진행 중인 스캔이 쓰는 항목은 한도 안에 만들어지거나 바뀐다. 두 배를 기준으로 하면, 취소가 늦게 전해지는 경우까지 넉넉히 두고도 진행 중인 스캔의 항목을 지우지 않는다. 다른 worker의 스캔도 같은 한도를 따른다.
- 스캔을 시작할 때마다 하면 worker가 다시 시작한 뒤 첫 스캔에서 정리되고, 따로 도는 고루틴이나 시계가 필요 없다.
- `HOME`을 두는 이유: 스캐너의 설정과 캐시가 있는 곳이다. 진행 중인 스캔이 읽기만 하는 오래된 파일도 있을 수 있어, 바뀐 시각만으로 지우면 실행 중인 스캐너가 쓰는 파일을 지울 수 있다.

## 검토한 다른 방법

- worker가 시작할 때 두 폴더를 모두 비우기: 같은 폴더를 쓰는 다른 worker의 진행 중인 스캔을 깨뜨린다.
- worker마다 하위 폴더를 따로 쓰고 시작할 때 자기 폴더만 비우기: worker ID는 시작할 때마다 새로 정해지므로, 죽은 worker의 폴더는 여전히 아무도 지우지 않는다.
- 데이터베이스에서 실행 중인 스캔을 조회해 그 밖의 사본 폴더를 지우기: 사본 폴더는 스캔 ID로 알 수 있지만 스캐너 임시 폴더의 항목은 어느 스캔의 것인지 알 수 없다.
