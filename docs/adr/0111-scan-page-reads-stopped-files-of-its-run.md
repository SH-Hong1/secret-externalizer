# 확인 스캔 화면도 실행의 멈춘 파일을 읽는다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

확인 스캔의 결과는 적용 결과 화면과 스캔 화면이 같은 틀(`confirmation`)로 보인다. 적용 결과 화면은 실행의 항목을 읽어, 바꾸던 중에 멈춘 파일(쓰는 중으로 남은 위치가 있고 적용된 위치가 없는 파일)이 있으면 "다시 찾지 못했지만 멈춘 파일의 값은 이 확인에 들지 않을 수 있다"고 보였다. 스캔 화면은 실행의 항목을 읽지 않아, 같은 스캔에 대해 "외부화한 값이 모두 사라졌습니다"나 "검사한 범위에서는 다시 발견되지 않았습니다"를 보였다(#109).

## 결정

확인 스캔이 성공했고 다시 찾은 항목이 없으면, 두 화면 모두 그 실행의 항목을 읽어 멈춘 파일 수를 센다. 하나라도 있으면 두 화면 모두 "unsure" 문구를 보인다. 판단은 두 화면이 함께 쓰는 `readConfirmation`과 `newConfirmation`에 있다. 다시 찾은 항목이 있으면 지금처럼 그 수를 보이고, 실행의 항목은 읽지 않는다.

## 이유

- 같은 스캔의 결과를 두 화면이 다르게 말하면, 스캔 화면만 본 사람은 확인이 끝났다고 믿는다. 멈춘 파일은 값이 바뀌었는지 기록이 모르므로 확인이 끝났다고 말할 수 없다(0041).
- 다시 찾은 항목이 있으면 화면이 이미 다시 점검하라고 안내하므로 멈춘 파일을 따로 말하지 않는다. 그 경우 실행의 항목을 읽을 필요도 없다.

## 검토한 다른 방법

- **멈춘 파일 수를 스캔 행에 저장한다.** 실행을 닫을 때 정해 두면 화면이 항목을 읽지 않아도 되지만, 나중 점검이 쓰는 중 위치를 맞추면(R1) 저장한 수와 기록이 어긋난다. 항목에서 그때 세면 두 화면이 언제나 같은 기록을 본다.
- **스캔 화면은 결과만 보이고 적용 결과 화면으로 안내한다.** 스캔 화면의 "모두 사라졌습니다"가 그대로 남아 틀린 말을 한다.
