# 첫 줄이 셸 shebang인 파일도 셸 스크립트로 본다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

셸 스크립트인지는 확장자(`.sh`, `.bash`, `.ksh`)로만 정했다(0119). 그래서 `bin/start`처럼 확장자 없이 `#!/bin/sh`로 시작하는 스크립트는 셸 규칙(`rules/opengrep/shell.yml`)이 읽지 않아 `sshpass -p` 비밀번호를 찾지 못했다. 다른 규칙이 찾은 값은 적용이 `${ext.db.main.password}`로 바꾸어, 셸이 펼치지 못하는 표기가 들어갔다(`bad substitution`). 작은따옴표 안의 placeholder 처리(0121)와 값 풀기의 셸 문법도 이 파일에는 걸리지 않았다(#203).

확장자와 달리 첫 줄은 파일 이름만으로 알 수 없다. 판정 화면, 적용 목록, 리포트는 프로젝트 파일을 읽지 않으므로, 스캔이 본 것을 저장해 두어야 한다.

## 결정

1. **셸 스크립트의 기준.** `triage.ShellFile(파일, 내용)`은 확장자가 `.sh`, `.bash`, `.ksh`(대소문자 무시)이거나, 해독한 내용의 첫 줄(끝의 CR 하나는 뺀다)이 sh, bash, ksh를 실행하는 shebang이면 참이다. shebang은 `#!` 뒤의 경로(`#!/bin/sh`, `#! /bin/bash -e`)나 `env`와 그 옵션 뒤의 이름(`#!/usr/bin/env bash`, `#!/usr/bin/env -S bash -e`)이다. 확장자가 다른 파일도 첫 줄이 이러면 셸 스크립트다. `zsh`, `dash`는 넣지 않는다.
2. **스캔이 저장한다.** 스캔은 항목마다 그 파일이 셸 스크립트인지(`finding.Finding.Shell`)를 정해 `finding.shell` 열에 저장하고, 그 항목을 다시 찾는 스캔마다 고쳐 쓴다. 마이그레이션 `0014_finding_shell.sql`은 이미 저장된 항목을 확장자로 채운다.
3. **읽는 쪽은 저장된 값을 따른다.** 판정 목록과 상세(`triage.Member.Shell`), 적용 목록(적용 항목의 finding), 리포트가 경로 대신 이 열을 읽는다. 0119의 SQL 상수 `shellPatterns`는 없앴다. 적용의 placeholder 형식(`triage.Name.For`)과 키를 지울 수 없는 파일 판단도 member의 값을 따른다. 값 풀기(`literal`)는 파일 내용을 받으므로 같은 함수로 직접 판단한다.
4. **셸 규칙의 짝.** 셸 규칙마다 id가 `-shebang`으로 끝나는 짝을 둔다. 짝은 셸 확장자 파일을 빼고(`exclude`) 다른 모든 파일을 읽되, 첫 패턴이 "첫 줄이 셸 shebang인 파일 전체"에 맞는 정규식이라서 나머지 패턴은 그런 파일 안에서만 맞는다(opengrep의 `patterns`는 맞은 구간의 교집합이다). 이 정규식은 앞의 바이트 순서 표시(BOM)를 허용한다. 스캔은 BOM을 뺀 내용으로 판단하기 때문이다.

## 이유

- 스캐너가 셸 규칙으로 읽는 파일과 적용이 셸 형식으로 바꾸는 파일이 같아야 한다(0119와 같은 이유). 그래서 shebang의 기준도 Go 함수와 규칙의 정규식이 같은 경우를 같게 판단하도록 맞추고, 규칙 사례(`rule-cases/scripts/start`, `backup`, `notes`, `tool`)와 `TestShellFile`이 같은 경우들을 본다.
- 판단을 저장하지 않으면 web이 프로젝트 파일을 읽어야 하는데, web은 프로젝트 폴더를 읽지 않는다. 열은 항목(파일) 단위라서, 같은 파일의 항목이 여럿이어도 값은 같다.
- 확장자가 없는 파일만이 아니라 모든 파일에 shebang을 보는 것은, opengrep의 경로 패턴으로 "확장자가 없음"을 나타낼 수 없기 때문이다(`*.*`를 빼면 `v1.2/run`처럼 점이 든 폴더 안의 파일도 빠진다). 셸 확장자는 원래 규칙이 읽으므로 짝에서 빼, 한 파일을 두 규칙이 읽지 않는다.
- `zsh`는 셸 규칙이 읽는 확장자에도 없다(0119). `dash`는 드물어 넣지 않았다. 넣을 때 Go 정규식과 규칙 정규식을 함께 고친다.

## 검토한 다른 방법

- **스캔 결과에 셸 파일 목록을 따로 저장(스캔별 표).** 항목이 없는 파일까지 저장하게 되고, 읽는 쿼리마다 표를 이어야 한다. 화면이 쓰는 것은 항목이 있는 파일뿐이다.
- **규칙을 확장자 없는 파일에만 걸기(`exclude: ["*.*"]`).** opengrep이 폴더 이름에도 이 패턴을 적용해 점이 든 폴더의 스크립트가 빠졌다.
- **규칙 하나에 두 경우를 합치기.** 정규식은 파일 이름을 볼 수 없어, 확장자가 `.sh`이면서 shebang이 없는 파일과 shebang 파일을 한 규칙으로 고를 수 없다.
- **적용 시 파일을 읽어 판단하고 화면은 확장자로 두기.** 판정 화면의 이름 안내와 적용 결과가 어긋난다.
