# 짧은 접속 정보 구성 요소는 같은 URL이 나오는 모든 자리에서 가린다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

주변 줄은 그 스캔이 어느 파일에서든 찾은 4바이트 이상의 값이 나오는 모든 자리를 가린다(0021). 더 짧은 값은 다른 낱말 안에서도 자주 맞아 쓰지 않는다. 접속 문자열을 구성 요소로 나눈 뒤(0026) 4바이트보다 짧은 포트(`22`)와 계정(`sa`)은 그 파일의 자기 자리에서만 가려졌다. 같은 URL이 규칙이 보고하지 않은 자리(주석, 다른 파일의 줄)에 있으면 `# backup jdbc:mysql://sa:****@****:22/shop`처럼 짧은 구성 요소만 보였고, 그 줄은 다른 항목의 주변 줄로 DB에 저장되었다(#111). 테스트로 재현했다.

## 결정

1. 주변 줄에서 가릴 것의 목록(`maskPatterns`)에, 나눈 URL 가운데 4바이트보다 짧은 구성 요소가 있는 것을 더한다. 이 항목은 URL의 글자 전체로 찾되 그 짧은 구성 요소의 자리만 가린다.
2. 4바이트 이상인 구성 요소는 지금처럼 값으로 어디서든 가린다. URL의 나머지 부분(scheme, DB 이름 등)은 가리지 않는다.
3. URL 글자 전체가 이미 통째로 가리는 값이면(나누지 못한 결과의 값 등) 더하지 않는다.

## 이유

- 짧은 값을 낱말 단위로 어디서든 가리면 주변 줄을 알아볼 수 없게 되지만(0021), URL 글자 전체가 같은 자리는 같은 값이 분명하므로 그 안의 짧은 구성 요소만 가려도 오탐이 없다.
- URL 전체를 통째로 가리면 호스트와 DB 이름처럼 이미 따로 다루거나 비밀이 아닌 부분까지 가려, 0026이 구성 요소 단위로 바꾼 뜻과 어긋난다.
- 찾기는 기존 색인(앞 4바이트로 묶음)을 그대로 써서 파일을 한 번만 훑는다.
- 키를 읽은 범위가 가리는 범위와 겹치면 키를 비운다(0053). 새로 가리는 범위는 URL 안쪽뿐이라 URL 앞에서 읽는 키에는 영향이 없다.

## 검토한 다른 방법

- **짧은 구성 요소도 값으로 어디서든 가리기.** `22`, `sa`가 모든 숫자와 낱말 안에서 가려져 주변 줄을 읽을 수 없다.
- **나눈 URL을 통째로 다른 자리에서 가리기.** 위의 이유로 버렸다.
- **같은 파일 안에서만 찾기.** 다른 파일의 같은 URL이 남는다.
