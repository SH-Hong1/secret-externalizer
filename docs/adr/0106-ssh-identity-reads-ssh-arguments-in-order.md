# ssh의 -i를 인자 순서대로 읽어 원격 명령과 가른다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

규칙 `shell-ssh-identity`는 ssh, scp, sftp 줄의 `-i` 뒤 인자를 키 파일로 보고한다. 원격 명령의 `-i`(`sed -i`)와 가르려고 `user@host` 뒤나 앞에서 열린 따옴표 안의 `-i`는 보고하지 않았다(0052). 그래서 따옴표와 `user@` 없이 쓴 원격 명령(`ssh host sed -i s/a/b/ 파일`)의 `-i` 뒤 인자가 키 파일로 보고되었다(0052의 "잘못 보고하는 것", #183). 또 `\bssh\b`가 `ssh-keygen`의 앞부분에도 맞아 `ssh-keygen -i -f 파일`의 `-f`가 키 파일로 보고되었다.

## 결정

1. **ssh는 인자를 차례로 읽는다.** OpenSSH의 ssh는 옵션, 목적지, 다시 옵션을 읽고, 그 뒤 첫 단어부터가 원격 명령이다. 규칙은 이 순서로 단어를 지나며, 인자를 받는 옵션(`-B -b -c -D -E -e -F -I -J -L -l -m -O -o -p -Q -R -S -W -w`)은 그 인자까지 한 단어로 건너뛴다. 원격 명령이 시작되기 전의 `-i`만 키 파일로 보고한다. `ssh -p 2222 host -i 키 uptime`의 키는 보고하고, `ssh host sed -i …`와 `ssh -t host -v sed -i …`는 보고하지 않는다.
2. **scp와 sftp는 지금 규칙을 그대로 쓴다.** 둘은 원격 명령이 없으므로 원래의 오탐이 생기지 않는다.
3. **명령 이름 앞뒤를 본다.** `ssh`, `scp`, `sftp` 앞에 글자, 점, 하이픈이 붙거나 ssh 뒤에 공백이 아닌 글자가 오면(`ssh-keygen`) 그 명령으로 보지 않는다.

## 이유

- 0052에서 정규식 하나로는 옵션마다 인자가 있는지 알아야 해서 미뤘지만, ssh의 옵션 글자는 정해져 있고 많지 않다. 인자를 받는 옵션과 받지 않는 옵션을 글자 집합 둘로 적으면 정규식 하나로 읽을 수 있다.
- 0052의 원칙대로, 원격 명령의 인자를 키 파일로 보고하면 적용이 명령의 인자를 placeholder로 바꿀 수 있다.

## 검토한 다른 방법

- 원격 명령에 흔한 명령 이름(`sed`, `perl`)을 따로 막기: 명령마다 목록을 늘려야 하고 `-i`를 쓰는 다른 명령은 여전히 보고된다.
- scp와 sftp에도 같은 읽기를 쓰기: 원격 명령이 없어 얻는 것이 없고, 리눅스의 scp는 피연산자 뒤의 옵션도 받으므로 차례 읽기가 오히려 키를 놓칠 수 있다.

## 남은 한계

- 옵션 여러 개를 붙여 쓰고 그 끝이 `-i`인 모양(`-ti 키`)은 지금처럼 보고하지 않는다.
- 따옴표 안의 원격 명령이 다시 ssh를 부르면(`ssh h 'ssh -i 키 x'`) 그 안의 키는 지금처럼 보고한다. 원격 호스트의 키 파일 이름이다.
