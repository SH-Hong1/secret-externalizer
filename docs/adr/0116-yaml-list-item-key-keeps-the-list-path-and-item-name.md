# YAML 목록 항목의 키는 목록 위의 경로와 항목의 name을 담는다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

0053은 YAML 값의 키를 위쪽 키를 이은 경로로 읽되, 목록 항목(`- name: …`)에서 경로를 끊고 목록 안의 값은 목록 항목 아래의 키만 쓰게 했다. 그래서 다음 두 비밀번호는 모두 키 `password`를 받는다.

```yaml
servers:
  - name: dev
    password: dev-only-fake-a
  - name: live
    password: dev-only-fake-a
```

값이 같으면 두 자리는 한 항목이 되어 같은 placeholder로 적용되고, 값이 다르면 추천 이름이 겹친다. 다른 목록(`mail.servers`, `db.servers`)에 있는 `password`도 구별되지 않는다(이슈 #65). 0053이 막으려던 "환경별 값이 한 이름으로 합쳐지는 일"이 목록에서는 그대로 남아 있었다.

## 결정

1. **목록 항목에서 경로를 끊지 않는다.** 목록 안의 값도 목록의 키와 그 위의 경로를 받는다. 목록 항목의 대시가 목록 키와 같은 열에 있는 쓰기(`servers:` 다음 줄의 `- name: …`)도 같다.
2. **목록 항목이 자기 키로 `name`이나 `id`를 가지면 그 값을 목록 키 바로 뒤에 붙인다.** 위 예의 키는 `servers.dev.password`, `servers.live.password`다. Kubernetes의 `env: - name: DB_PASSWORD value: …`는 `env.DB_PASSWORD.value`가 된다.
   - 항목 자기 키만 본다. 항목 안에서 더 깊이 있는 `name`(`- db: {name: …}`)은 쓰지 않는다.
   - `name`과 `id` 가운데 항목에서 먼저 나오는 것을 쓴다. 값보다 아래에 있어도 된다.
   - 값은 따옴표를 벗기고 줄 끝 주석을 뺀 글자다. 키 글자(영문, 숫자, `.`, `_`, `-`)만으로 되어 있지 않거나 비었으면 붙이지 않는다. 키를 읽는 값 자신이 `name`의 값이면(`- name: 비밀 값`) 붙이지 않는다.
   - `name`이나 `id`가 없는 항목은 목록 키 뒤에 아무것도 붙이지 않는다(`servers.password`).
3. 대시가 있는 줄의 키(`- db:`)는 그 아래의 더 깊은 키들의 부모다(`servers.db.password`). 목록 안의 목록도 같은 규칙을 거듭 쓴다(`a.x.b.y.password`).
4. 붙인 `name` 값도 키의 한 조각(파일의 바이트 구간)이다. 0053의 결정 3대로 그 구간이 주변 줄에서 가리는 범위와 겹치면 키 전체를 비운다.

## 이유

- 목록은 같은 모양의 설정(서버, 데이터 소스, 환경 변수)을 여러 벌 적는 자리라서 같은 키가 반복된다. 목록 안의 순서나 항목의 이름이 없으면 그 반복을 구별할 수 없다.
- 항목의 `name`과 `id`는 그 항목을 사람이 부르는 이름이다. 순번(`servers.0.password`)과 달리 위에 항목을 더하거나 지워도 바뀌지 않는다. 순번을 쓰면 앞 항목을 지웠을 때 뒤 항목이 앞 항목의 키를 받아, 값이 같으면 다른 환경의 판정과 이름을 말없이 이어받는다. 0053이 막으려던 일이다.
- 이름이 없는 항목을 나누지 못하는 것은 남는다. 틀렸을 때 둘이 한 항목으로 남는 것은 지금과 같고, 목록 위의 경로가 붙어 다른 목록과는 구별된다.
- `name` 값이 비밀이라면 스캔이 그 값을 찾아 가리는 범위에 넣으므로 키가 비워진다. 찾지 못한 글자라면 비밀 값이 아니라 설정의 이름이다.

## 검토한 다른 방법

- **항목의 순번을 붙인다.** 이름이 없는 항목도 나뉘지만 위의 이유로 다른 항목의 판정을 이어받을 수 있다.
- **항목의 첫 키 값을 붙인다(`name`, `id`가 아니어도).** `- host: db1.invalid`, `- user: shopadmin`처럼 호스트나 계정이 키에 들어간다. 계정은 스캔이 찾으면 가려지지만 찾지 못한 계정도 키에 남는다.
- **목록 위의 경로만 붙인다.** 다른 목록과는 구별되지만 이슈의 예(한 목록의 두 환경)는 그대로다.

## 알려진 한계

- 키가 바뀐 자리(YAML 목록 안의 값)는 다음 스캔에서 키가 다른 새 항목이 되어 전의 판정을 이어받지 않는다(이슈 #56).
- `name`이나 `id`가 없는 항목, 그 값이 키 글자가 아닌 항목(`name: live db`)의 같은 값은 지금처럼 나뉘지 않는다.
- 흐름 모양(`- {name: live, password: …}`)과 여러 줄 값은 0053과 같이 다룬다.
