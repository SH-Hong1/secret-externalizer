# 키 이름에 쓰는 낱말인 값도 그 낱말이 든 키를 비운다

- 날짜: 2026-11-25
- 상태: 확정

## 배경

스캔은 키가 스캔에서 찾은 값을 담지 않게 하려고, 키 조각이 주변 줄에서 가리는 범위(이 파일의 값, 위치를 정하지 못한 값이 있을 수 있는 자리, 스캔 전체에서 찾은 값의 모든 등장)와 겹치면 키를 비운다(`internal/scan/merge.go`의 `spotKey`). 공개 예제의 주석 속 dataSource bean은 계정 `user`, 비밀번호 `password`를 쓴다. 이 값들이 항목이 되자 같은 파일의 `username`, `password` 키 이름이 가린 범위와 겹쳐, 주석 밖의 bean을 포함해 그 파일의 계정과 비밀번호 항목이 모두 키를 잃었다(#145).

이슈는 키를 버리는 조건을 좁힐지를 물었다. 가린 글자가 `user`, `password` 같은 자격 증명 키 낱말이면 키를 비우지 않는 수정을 PR #147에 올렸으나, CI 규칙 검토가 Security 위반으로 막았다. 실제 비밀 값이 마침 그 낱말이면 키 `dataSource.password`가 그 값을 글자 그대로 DB 컬럼에 담는다. `AGENTS.md`의 Security 절은 비밀 값이 DB 컬럼에 나타나지 않는다고 하고, 예외는 fingerprint와 `finding.Preview`의 미리보기뿐이다. #145를 고치는 어떤 방법도 키 컬럼에 찾은 값과 같은 글자를 남기게 된다. 사용자가 지금 동작을 유지하기로 정했다.

## 결정

1. 키 조각이 가린 범위와 겹치면, 가린 글자가 무엇이든 키를 비운다. 지금 동작을 그대로 둔다.
2. 이 동작을 `TestHandle_KeyNeverHoldsValueThatIsAKeyWord`가 붙잡는다.
3. 공개 예제 검증의 기대 목록(`internal/apply/testdata/public-sample.golden`)에서 `context-datasource.xml`의 계정과 비밀번호 항목은 키가 빈 채로 남는다.

## 이유

- 키가 비어도 항목은 찾고, 판정과 적용도 된다. 잃는 것은 판정 화면의 키 이름과 그 키로 정하는 묶음, 추천 이름의 정확도다.
- 키 낱말이 키에 있는 것은 키 때문이라 정보로는 값을 알려 주지 않는다고 볼 수 있다. 하지만 보안 규칙은 글자를 기준으로 쓰여 있고, 규칙 검토도 그렇게 읽는다. 보안 규칙에 예외를 더하는 것은 이 이슈의 이득보다 무거운 일이다.

## 검토한 다른 방법

- 가린 글자가 자격 증명 키 낱말(`user`, `username`, `password`, `secret`, `token` 등)이면 키를 비우지 않기: PR #147의 첫 커밋. 위 배경의 이유로 Security 위반이다.
- `AGENTS.md` Security 절에 "자격 증명 키 낱말 목록과 같은 값은 키에 남을 수 있다"는 예외를 더한 뒤 위 방법 적용: 보안 규칙을 느슨하게 하는 일이라 하지 않았다.
- 값이 바로 그 자리의 키 조각 안에 있을 때만 버리기: 키 조각 `password`와 값 `password`는 글자로 구별되지 않는다.
