# 셸의 작은따옴표 안 placeholder는 따옴표를 닫고 큰따옴표로 넣는다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

셸 스크립트에서 비밀 값은 `sshpass -p 'dev-only-fake-sshpass'`처럼 작은따옴표로 감싸는 일이 많다. 적용은 이 값을 `${EXT_DEPLOY_SSH_PASSWORD}`로 바꾸어 `sshpass -p '${EXT_DEPLOY_SSH_PASSWORD}'`를 남겼다. 셸은 작은따옴표 안을 펼치지 않으므로 스크립트는 비밀번호 대신 `${EXT_DEPLOY_SSH_PASSWORD}`라는 글자를 넘긴다. 적용은 성공으로 기록되고 이를 알리지 않았다(#200).

## 결정

- 외부화하는 자리가 셸 파일(`triage.ShellFile`)의 작은따옴표 문자열 안에서 시작하면, 적용은 그 자리에 `'"${EXT_NAME}"'`를 쓴다. 작은따옴표를 닫고, 큰따옴표 안에서 placeholder를 펼치고, 작은따옴표를 다시 연다. `'dev-only-fake'`는 `''"${EXT_NAME}"''`가, `'a dev-only-fake b'`는 `'a '"${EXT_NAME}"' b'`가 된다.
- 작은따옴표 안인지는 `literal.ShellSingleQuoted`가 판단한다. 값 풀기(`literal.Value`)와 같이 그 자리가 있는 줄의 처음부터 읽는다.
- 적용 계획과 점검 화면, 계획 지문은 바꾸지 않는다. 바꿔 쓸 글자는 worker가 파일을 읽고 값을 풀 때 정한다.

## 이유

- 작은따옴표 안의 값은 셸 스크립트에서 가장 흔한 모양이다. 건너뛰면(새 사유로 알리고 옮기지 않으면) 셸 스크립트의 비밀 대부분이 소스에 남는다.
- `'…'"…"'…'`는 셸이 이어 붙이는 한 단어이므로 명령의 인자 수와 그 밖의 글자는 그대로다. 큰따옴표 안의 `${EXT_NAME}`은 값에 공백이나 특수 문자가 있어도 한 인자로 펼쳐진다.
- 판단은 파일 내용이 있어야 하므로 계획(데이터베이스만 읽는다)에서 할 수 없다. 이 글자는 계획 지문에 들지 않으므로 사람이 확인한 계획은 그대로다.

## 한계

- 여러 줄에 걸친 작은따옴표 문자열과 `<<'EOF'`처럼 펼치지 않는 here-document는 줄 하나만 읽어서는 알 수 없어 그대로 `${EXT_NAME}`이 들어간다. 값 풀기의 한계와 같다.
- 확장자가 없는 셸 스크립트는 셸 파일로 보지 않으므로 이 규칙도 걸리지 않는다(#203).

## 검토한 다른 방법

- 새 사유(`single-quoted`)로 건너뛰고 화면에 알리기: 셸 비밀의 흔한 모양을 옮기지 못한다.
- 값을 감싼 작은따옴표째로 `"${EXT_NAME}"`로 바꾸기: 더 짧지만 바꿀 범위가 스캔이 찾은 범위보다 넓어져, 범위와 지문을 확인하는 단계를 모두 고쳐야 한다. 값이 따옴표 문자열의 일부일 때는 쓸 수 없다.
