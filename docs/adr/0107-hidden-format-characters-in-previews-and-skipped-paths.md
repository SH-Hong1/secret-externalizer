# 미리보기와 건너뛴 파일 경로의 유니코드 형식 문자

- 날짜: 2026-11-26
- 상태: 확정

## 배경

비밀 값의 미리보기(`finding.Preview`)는 앞 네 글자에 제어 문자가 있으면 마스크만 보이고, 건너뛴 파일 목록은 제어 문자가 든 경로를 저장하지 않는다(0021, 0030). 그런데 방향 바꿈(U+202E 등), 폭 없는 공백(U+200B), 바이트 순서 표시(U+FEFF) 같은 유니코드 형식 문자(Cf)와 줄·문단 구분자(U+2028, U+2029)는 제어 문자가 아니어서 그대로 남았다(#185). 이 글자는 보이지 않거나 주변 글의 방향을 바꿔, 화면의 미리보기나 경로가 실제 값이나 이름과 다르게 읽힐 수 있다.

## 결정

1. 미리보기의 앞 네 글자에 제어 문자, 형식 문자(Cf), 줄 구분자(Zl), 문단 구분자(Zp), `U+FFFD`가 있으면 마스크(`****`)만 보인다. 네 글자 뒤에 있는 것은 미리보기에 들어가지 않으므로 지금처럼 앞 네 글자를 보인다.
2. 건너뛴 파일 목록은 위 글자가 든 경로를 저장하지 않는다. 그 파일은 지금처럼 건너뛴 수에 센다.

## 이유

- 미리보기는 사람이 값을 알아보는 단서일 뿐이므로, 단서가 거짓일 수 있으면 보이지 않는 편이 낫다. 제어 문자에 쓰던 규칙을 같은 성질의 글자로 넓힌 것이다.
- 건너뛴 경로는 처음 200개만 저장하는 참고용 목록이다. 수는 그대로 세므로 빠진 경로가 있다는 것은 남는다.

## 검토한 다른 방법

- 형식 문자를 `U+FFFD`나 `‮` 같은 표기로 바꿔 보이기: 미리보기는 앞 네 글자의 길이가 바뀌고, 경로는 실제 이름과 다른 글을 보이게 된다. 지금 제어 문자를 다루는 방식과도 다르다.
- 형식 문자가 든 경로의 파일을 스캔하지 않기(제어 문자가 든 경로처럼): 그 파일의 비밀 값을 놓친다. 제어 문자가 든 경로는 데이터베이스가 받지 못해 건너뛰는 것이고, 형식 문자는 저장할 수 있다. 그래서 항목의 파일 경로와 주변 줄에는 형식 문자가 그대로 남는다. 이것을 화면에서 드러내는 일은 #186에 남긴다.
