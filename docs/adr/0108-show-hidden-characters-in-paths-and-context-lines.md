# 파일 경로와 주변 줄의 보이지 않는 글자를 코드 포인트로 보이기

- 날짜: 2026-11-26
- 상태: 확정

## 배경

미리보기와 건너뛴 파일 목록은 유니코드 형식 문자(Cf)와 줄·문단 구분자를 거른다(0107). 항목의 파일 경로와 주변 줄은 그 파일을 스캔해야 하므로 거를 수 없어, 이 글자를 그대로 저장하고 판정 화면, 적용 화면, 감사 기록, 리포트와 PDF에 그대로 보였다(#186). 방향 바꿈(U+202E)이 든 경로는 실제 이름과 다른 순서로 읽히고, 폭 없는 공백(U+200B)은 보이지 않아 같은 이름처럼 보이는 두 파일을 구별할 수 없다. 주변 줄도 같다.

## 결정

1. 화면이 파일 경로와 주변 줄을 보일 때 탭이 아닌 제어 문자, 형식 문자(Cf), 줄 구분자(Zl), 문단 구분자(Zp)를 `<U+202E>`처럼 코드 포인트로 바꿔 보인다. 템플릿 함수 `visible`이 바꾸고, 판정 화면(목록, 위치, 주변 줄, 고객정보의 파일), 적용 화면과 적용 결과 화면, 감사 기록, 리포트가 이것을 쓴다. PDF는 리포트와 같은 템플릿이므로 같다.
2. 저장하는 값은 바꾸지 않는다. 폼이 서버로 돌려보내는 파일 경로(고객정보 판정 폼의 숨은 필드)도 원래 경로 그대로다.

## 이유

- 경로와 주변 줄은 사람이 위치를 찾아가는 단서다. 글자를 감추거나 지우면 실제 이름과 다른 글을 보이게 되고, 그대로 두면 다르게 읽힌다. 코드 포인트로 쓰면 이름에 그런 글자가 있다는 사실과 자리가 함께 보인다.
- 화면에서만 바꾸므로 적용, manifest, 같은 위치를 찾는 비교는 실제 경로를 그대로 쓴다.
- 탭은 주변 줄의 들여쓰기에 흔히 쓰이고 `<pre>` 안에서 보이므로 그대로 둔다. 제어 문자는 경로에서는 이미 건너뛰는 파일이지만(0021) 주변 줄에는 남을 수 있어 함께 다룬다.

## 검토한 다른 방법

- 글자를 지우고 보이기: 지운 글자가 있다는 것을 알 수 없고, 서로 다른 두 경로가 같게 보인다.
- `U+FFFD`로 바꾸기: 어떤 글자였는지 알 수 없고, 디코딩하지 못한 바이트와 구별되지 않는다.
- 표기를 `<span>`으로 감싸 다른 색으로 보이기: 입력을 `template.HTML`로 바꿔야 해 규칙에 어긋난다. 글자 그대로 `<U+202E>`라는 이름의 파일과 구별되지 않는 한계는 남지만, 그런 이름은 드물고 위치를 찾는 데 걸림이 되지 않는다.
- 저장할 때 바꾸기: 적용과 manifest가 실제 파일을 찾지 못한다.
