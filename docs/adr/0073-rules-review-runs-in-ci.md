# AI 규칙 검토는 PR마다 CI에서 한다

- 날짜: 2026-11-25
- 상태: 확정

## 배경

AGENTS.md의 규칙 가운데 주석과 기록, Security 절처럼 린터가 보지 못하는 것은 턴이 끝날 때 Claude Code hook(`stop-review.sh`, 0014)이 검토했다. 검사를 git hook과 CI로 옮기면서(0072) 이 검토를 어디서 할지 정해야 했다.

## 결정

- CI의 `review` 작업이 PR마다 `anthropics/claude-code-action`으로 검토한다. 검토자는 읽기 도구(`Read`, `Grep`, `Glob`)만 쓰고, 지시문은 `.github/review-prompt.md`, 검토 대상은 PR의 diff다.
- Go 소스, `go.mod`, 템플릿, SQL이 바뀌지 않은 PR은 검토하지 않고 통과한다.
- 검토자는 위반 목록을 JSON으로 낸다. `scripts/review-verdict.sh`가 그 목록으로 체크의 성패를 정하고 PR 댓글 하나를 남긴다. 다시 실행하면 같은 댓글을 고쳐 쓴다.
  - 위반이 없으면 통과한다.
  - 위반이 있으면 실패한다. PR에 `review: override` 라벨이 있으면 Security 절이 아닌 위반은 통과시킨다.
  - 판정을 읽을 수 없으면(API 장애, 시간 초과, 사용 한도, 형식이 맞지 않는 출력) 실패한다. 이때는 라벨로도 통과시킬 수 없고, 작업을 다시 실행해야 한다.
- 인증은 저장소 secret `CLAUDE_CODE_OAUTH_TOKEN`이나 `ANTHROPIC_API_KEY`다. 둘 다 없으면 실패한다.
- 검토자는 코드 줄이나 값을 인용하지 않는다. 공개 PR의 댓글에 비밀 값이 남지 않게 하기 위해서다.
- 이 체크는 `main` 브랜치 보호의 필수 체크다.

## 이유

- PR마다 빠짐없이 돌고, 누가 어떤 도구로 커밋했든 같은 검토를 받는다.
- 턴 종료를 막지 않으므로 작업 중간에는 비용이 들지 않는다.
- 판정이 없을 때 통과시키면 검토하지 않은 Security 위반이 필수 체크를 지나 `main`에 들어갈 수 있다. hook과 달리 CI는 다시 실행하기 쉬워서 실패로 두는 비용이 작다.
- 라벨은 검토자가 잘못 막을 때의 출구다. Security 위반은 잘못 막는 비용보다 놓치는 비용이 커서 출구를 두지 않는다.

## 검토한 다른 방법

- 필요할 때 손으로 돌리는 `make review`: 비용은 없지만 빠뜨릴 수 있다.
- AI 검토를 없애고 린트와 사람의 검토만 남기기(app-surveyor와 같은 방식): 주석과 Security 규칙을 강제할 곳이 없어진다.
- action이 PR에 리뷰 댓글을 직접 쓰게 하기: 체크의 성패를 정할 수 없고, 출력 형식을 보장할 수 없다.
