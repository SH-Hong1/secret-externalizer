# 조건에 막힌 점검은 파일을 읽지 않는다

- 날짜: 2026-11-26
- 상태: 확정

## 배경

적용은 조건에 막히면 파일을 읽기 전에 멈추지만, 점검은 저장소를 들여다볼 수 있으면 조건에 막혀도 대상 파일을 읽고 OpenBao로 지문을 확인했다. 그래서 막힌 점검의 위치 가운데 일부는 읽은 결과로 건너뜀(`nested-repository`, `value-mismatch` 등)이 되고, 나머지만 계획됨으로 남았다. 적용 화면은 막힌 점검의 계획됨 위치를 "점검하지 못함" 수로 보이는데, 저장소가 아니거나 git이 없어 파일을 읽지 못한 조건에서는 모든 위치가, 새 스캔이 있거나 커밋되지 않은 변경이 있는 조건에서는 읽고 남은 위치만 세어져, 같은 계획이 막힌 조건에 따라 다른 수로 보였다(예제에서 81~83, #106).

## 결정

점검도 적용처럼 앞 단계가 막는 조건을 하나라도 찾으면 대상 파일을 읽기 전에 멈춘다. 막힌 점검의 위치는 계획이 건너뛴 것(판정이 더는 허용되지 않음, 겹침, 고객정보 포함 등)을 빼고 모두 계획됨으로 남고, 적용 화면은 어느 조건에 막혔든 같은 수를 "점검하지 못함"으로 보인다.

## 이유

- 막힌 점검은 확인할 수 없고, 조건을 고친 뒤 다시 점검해야 한다. 그때 파일을 다시 읽으므로 막힌 점검에서 읽은 결과는 쓰이지 않는다.
- 화면은 막힌 점검의 건너뛸 위치를 보이지 않고 수만 보인다. 일부만 읽은 결과는 그 수를 흔들 뿐이다.
- 막힌 점검이 OpenBao에 값을 보내지 않으므로, 적용할 수 없는 실행이 비밀 값을 다루는 일이 줄어든다.
- 파일을 다 읽어야 알 수 있는 "적용할 수 있는 항목이 없음"은 다른 조건에 막힌 점검에서는 나오지 않는다. 다른 조건을 고친 뒤의 점검에서 나온다.

## 검토한 다른 방법

- 화면에서 계획됨과 읽은 뒤 건너뛴 위치를 함께 세기: 건너뜀 사유가 계획에서 나왔는지 읽기에서 나왔는지 web이 나눠야 하고, 읽지 않아도 될 파일과 OpenBao 요청은 그대로 남는다.
- 막힌 점검에서도 읽은 결과를 화면에 보이기: 조건을 고치기 전의 결과라 다시 점검하면 바뀔 수 있고, 조건에 따라 보이는 내용이 달라지는 문제가 그대로다.
