# 공개 예제로 스캔부터 확인 스캔까지 검증한다

- 날짜: 2026-11-25
- 상태: 확정

## 배경

스캔과 적용을 끝까지 도는 테스트는 `TestIntegration_ScanApplyRescan`(ADR 0049) 하나이고, 그 대상은 이 저장소가 직접 만든 예제 `legacy-shop`이다. 직접 만든 예제는 우리가 생각한 모양만 담는다. app-surveyor는 완료 기준에 "공개된 실제 프로젝트 하나에 실행해 본다"를 두고 전자정부 표준프레임워크의 공개 예제를 쓴다. 이 저장소도 실제 구조의 프로젝트로 확인할 길이 필요했다.

## 결정

- 대상은 전자정부 표준프레임워크의 `egovframe-web-sample`(Apache-2.0)이다. 이름, 주소, 커밋을 `scripts/samples.lock`에 고정한다. 받을 수 없게 되면 다른 공개 eGovFrame이나 Spring MVC 예제로 바꾸고 이 기록을 대체한다.
- `scripts/fetch-sample.sh`가 고정한 커밋만 저장소 밖(`~/.cache/secret-externalizer/samples/<이름>-<커밋>`)에 받고, 받은 HEAD가 그 커밋인지 확인한다. 이미 받은 사본이 그 커밋에 그대로 있으면 다시 받지 않는다. 예제의 소스와 결과는 저장소에 넣지 않는다.
- `make sample-check`가 예제를 받아 `TestIntegration_PublicSample`(`internal/apply`)을 돌린다. 이 테스트는 `SAMPLE_PROJECT_DIR`가 없으면 건너뛴다. 예제를 `.git` 없이 임시 작업 공간에 복사해 새 저장소로 커밋하고, 실제 스캐너, postgres, OpenBao, git으로 다음을 확인한다.
  1. 찾은 항목의 (파일, 분류, 종류, 설정 키) 목록이 `internal/apply/testdata/public-sample.golden`과 같다. 이 파일에는 값도 미리보기도 없다. 규칙이 바뀌어 목록이 달라지면 `make sample-check UPDATE_GOLDEN=1`로 다시 쓰고 그 차이를 PR에서 검토한다.
  2. 추천 판정대로 점검하고 적용한 뒤의 확인 스캔이 적용한 비밀(비밀번호, 토큰, 키, 기타)을 다시 찾지 않는다.
  3. 스캔이 보관한 원본 비밀이 어느 테이블에도, worker 로그에도 없다. 실패 메시지는 장소와 길이만 말하고 값을 쓰지 않는다.
  4. 적용이 바꾸거나 지운 파일은 자리를 적용한 파일과 manifest뿐이다.
- CI의 `sample` 작업이 같은 일을 한다. 필수 체크는 아니다.
- 기대 목록은 지금 동작을 그대로 담는다. 목록을 검토하다 찾은 오탐과 누락, 화면에서 찾은 결함은 Milestone "공개 예제 검증"의 Issue로 만들고 그 Issue에서 고친다.

## 이유

- 같은 명령으로 언제든 다시 돌릴 수 있어, 규칙이나 스캐너를 바꿀 때 실제 구조의 프로젝트에서 무엇이 달라지는지 PR에서 보인다.
- 커밋을 고정하므로 예제 저장소가 바뀌어도 결과가 흔들리지 않는다.
- 저장소에 남의 소스를 넣지 않는다. 라이선스와 크기 문제가 없고, 기대 목록에는 값이 없다.
- 외부 저장소를 받는 단계는 이 저장소와 상관없는 이유로 실패할 수 있어 필수 체크로 두지 않는다.

## 처음 돌렸을 때 확인한 것

- 예제는 158개 파일, 3.8MB다. 스캔은 메시지 파일 셋의 `confirm.required.user`를 계정 값으로 보고했다. 값은 유니코드 이스케이프로 쓴 안내 문장이라 오탐이다(#126).
- `context-datasource.xml`에서 주석으로 막아 둔 dataSource bean 셋의 URL, 계정, 비밀번호는 보고하지 않았다(#127).
- 위 둘 밖에 예제에는 비밀이나 접속 정보로 보이는 글이 없었다. 그래서 이 예제는 탐지의 폭보다 "실제 구조의 프로젝트에서 스캔, 적용, 확인 스캔이 실패 없이 돌고 값을 남기지 않는다"를 확인하는 데 쓸모가 있다.

## 실제 스택에서 확인한 것

2026-11-25에 이 저장소의 `main`으로 다시 빌드한 이미지(web, worker)를 띄우고, 예제를 작업 공간의 git 저장소로 두어 화면으로 끝까지 돌렸다(Docker VM 메모리 4GB).

| 단계 | 결과 |
|---|---|
| 프로젝트 등록, 스캔 | 스캔이 2초 안에 끝났다. 파일 158개, 건너뜀 4개(글꼴 3개, PNG 1개, "검사하지 못한 것"에 이름이 보임), 항목 3개 |
| 판정 화면 | 미리보기는 `\ub4****`, 주변 줄의 값은 `****`로 가려졌다. 계정 종류라 같은 값도 항목마다 묶음이 따로였고 "이 묶음 전체 합치기"가 보였다 |
| 원본 보기(admin) | 값이 보였고 감사 로그에 "원본 보기"가 먼저 남았다 |
| 판정 | 둘을 오탐으로 판정하자 남은 하나의 제안이 "오탐"으로 바뀌고 이름 칸이 비었다. 이름 없이 외부화를 누르면 400과 이름 규칙 안내가 보였고, 이름을 넣으면 저장되었다 |
| 점검, 적용 | 막는 조건 없이 "적용 가능", 적용 1곳. 소스에서는 그 한 줄이 `${ext.msg.confirm.account}`로 바뀌고 `secrets-manifest.yml`이 생겼다. 다른 파일은 바뀌지 않았다 |
| 확인 스캔 | 항목 2개(오탐으로 둔 두 곳). 적용 결과 화면이 "외부화한 값이 다시 발견되지 않았습니다"와 건너뛴 파일 안내를 보였다 |
| 리포트, PDF | 리포트의 일곱 절이 보였고, PDF는 200, `application/pdf`, 67KB였다 |
| 대시보드 | 외부화 1, 오탐 2, 남은 항목 0(지난 스캔 대비 -1), 추이 막대 둘 |
| 로그 | web, worker, applier, openbao, pdf 로그 600줄에 원본 값이 이스케이프 글자로도, 푼 문장으로도 없었고 ERROR가 없었다 |

화면에서 새로 찾은 결함은 없다. 브라우저 콘솔에는 `favicon.ico`의 404가 보인다.

## 검토한 다른 방법

- 사람이 화면으로만 한 번 확인하기(app-surveyor와 같은 방식): 가볍지만 다시 하려면 같은 수고를 반복해야 한다.
- 예제를 `testdata`에 복사하기: 남의 소스 158개 파일이 저장소에 들어오고, 라이선스 고지를 함께 관리해야 한다.
- 고정하지 않고 늘 최신 커밋 받기: 예제 저장소가 바뀌면 이 저장소의 PR이 이유 없이 실패한다.
