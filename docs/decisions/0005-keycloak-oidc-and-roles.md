# 로그인은 Keycloak OIDC, 역할은 user와 admin 두 가지로 한다

- 날짜: 2026-11-18
- 상태: 확정

## 배경

주로 개발자 PC에서 실행하는 도구지만, 마스킹되어 있어도 민감 정보를 다루므로 안전장치로 인증이 필요하다.

## 결정

- Keycloak OIDC(Authorization Code + PKCE)로 로그인한다.
- 세션은 valkey에 두고 쿠키에는 세션 ID만 담는다.
- 역할은 `user`와 `admin`이다. `user`는 프로젝트 등록, 스캔, 판정, 적용, 리포트, 대시보드를 쓰고 값은 마스킹된 상태로만 본다. `admin`은 여기에 더해 원본 값을 볼 수 있다.
- 원본 보기는 볼 때마다 OpenBao에서 읽고 캐시하지 않으며, 누가 언제 무엇을 봤는지 감사 로그에 남긴다.
- web과 worker는 사용자 로그인과 무관하게 AppRole로 OpenBao에 인증한다.

## 이유

- 보안 도구가 비밀번호 저장, 잠금, 재설정을 직접 구현하지 않는다.
- MFA와 비밀번호 정책을 Keycloak이 제공한다.
- 나중에 공용 서버나 사내 SSO로 옮길 때 설정만 바꾸면 된다.

## 검토한 다른 방법

- 앱 자체 계정(argon2id) + valkey 세션: 구성은 가볍지만 비밀번호 관리 전체를 직접 책임져야 한다.
- OpenBao의 OIDC provider 기능: 로그인 화면과 사용자 관리가 빈약하다.
