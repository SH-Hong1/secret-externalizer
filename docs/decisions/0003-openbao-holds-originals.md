# 원본 값은 OpenBao에만 두고 postgres에는 지문과 미리보기만 둔다

- 날짜: 2026-11-18
- 상태: 확정

## 배경

소스에서 값을 지우면 manifest에는 위치와 placeholder만 남는다. AWS 연동이 범위 밖인 1차에서도, 지운 값이 어딘가에 남아 있어야 나중에 담당자가 옮길 수 있다.

## 결정

- 비밀 값의 원본은 OpenBao KV v2에 보관한다.
- postgres에는 지문, 마스킹된 미리보기, 위치, 주변 코드(해당 값은 마스킹)만 저장한다.
- 지문은 OpenBao의 transit 기능으로 계산한 HMAC이다.
- 판정 전의 원본은 스캔 시점에 OpenBao의 임시 경로에 저장하고, 오탐으로 판정되면 지운다.
- 고객정보는 원본도 주변 줄도 저장하지 않는다. 종류, 위치, 건수만 남긴다.
- 적용 순서는 OpenBao 저장, 소스 치환, manifest 기록이다. OpenBao 저장에 실패하면 소스를 건드리지 않는다.

## 이유

- 탐지 도구의 DB가 평문 비밀 값의 집합소가 되어서는 안 된다.
- 짧은 비밀번호는 단순 해시에서 역산하기 쉬우므로, 키가 있어야 계산되는 HMAC을 쓴다.
- web은 소스를 읽을 수 없으므로, admin이 판정 중에 원본을 보려면 OpenBao에 있어야 한다.
- 고객정보를 OpenBao로 옮기면 개인정보 사본이 하나 더 생긴다. 로그의 주변 줄에는 탐지되지 않은 다른 고객정보가 섞여 있을 수 있다.
- 이후 AWS로 옮길 때 저장소만 바꾸면 된다.

## 검토한 다른 방법

- gitignore된 로컬 파일로 내보내기: 평문 파일이 개발자 PC에 남는다.
- 보관하지 않기: 원본을 git 히스토리나 백업에서 찾아야 한다.
