# manifest 형식

- 날짜: 2026-11-20
- 상태: 확정

## 배경

적용은 프로젝트 폴더에 `secrets-manifest.yml`을 쓴다. 어떤 placeholder를 어느 파일, 어느 줄에 썼고 값이 어디에 저장되었는지를 값 없이 적은 파일이다. 설계는 "이미 있으면 덮어쓰지 않고 읽어서 이어 쓴다"고 정했다. 이 파일은 사람이 고칠 수 있고, 파일 이름은 스캔한 저장소에서 오므로 믿을 수 없다(`:`, `#`, 따옴표, 줄바꿈, 맨 앞 `-`, `*`, `&`, `!`, 제어 문자가 들어갈 수 있다).

## 결정

1. `internal/manifest`가 YAML 라이브러리 없이 한 가지 모양만 쓰고 읽는다(계획 5 검토 항목 19).
   - 모양: `version: 1`, `entries:` 아래 항목마다 `name`, `category`, `action`, `store`, `locations`(`file`, `line`) 순서. 들여쓰기는 항목 2칸, 위치 6칸이다. 항목이 없으면 `entries: []`, 위치가 없으면 `locations: []`다. `line`이 0(제거한 파일)이면 `line` 줄을 쓰지 않는다. 끝에 줄바꿈 하나를 쓴다.
   - 줄바꿈: 첫 줄의 줄바꿈이 CRLF면 모든 줄이 CRLF여야 하고, 다시 쓸 때도 CRLF로 쓴다. 마지막 줄의 줄바꿈은 없어도 읽는다.
   - 스칼라: `^[A-Za-z0-9_./-]+$`에 맞고, `-`, `.`, 숫자로 시작하지 않으며, `null`, `true`, `false`, `yes`, `no`, `on`, `off`, `y`, `n`(대소문자 무시)이 아니면 따옴표 없이 쓴다. 그 밖에는 큰따옴표 안에 YAML 큰따옴표 스칼라의 이스케이프(`\"`, `\\`, `\n`, `\r`, `\t`, 기본 평면의 글자는 `\uXXXX`, 그 밖의 글자는 `\UXXXXXXXX`)로 쓴다. `"`, `\`, `unicode.IsPrint`가 아닌 글자(제어 문자, DEL, C1, 줄 구분자 U+2028, 방향 바꿈 U+202E, BOM 같은 형식 문자)는 언제나 이스케이프한다. 한글 같은 출력 가능한 글자는 그대로 쓴다.
   - 읽기는 쓰는 모양만 받는다. 따옴표 없는 값은 쓰는 쪽이 따옴표 없이 쓸 값일 때만, 따옴표 안에서는 쓰는 쪽이 그대로 쓰는 글자와 쓰는 쪽이 쓰는 이스케이프만 받는다. `\u`로 쓴 대리 문자(대리 쌍 포함), `\/`, `\b`, `\f`, 기본 평면의 글자를 `\U`로 쓴 것, U+10FFFF를 넘는 값은 받지 않는다. 다만 쓰는 쪽이 따옴표 없이 쓸 값을 큰따옴표로 감싼 것은 받고, 다시 쓸 때 따옴표 없이 쓴다. 그래서 "쓰는 모양만 받는다"는 글자 그대로가 아니라 읽은 값을 다시 쓰면 쓰는 모양이 된다는 뜻이다. `line`은 앞자리 0이 없는 1부터 999,999,999(`MaxLine`)까지의 수다.
   - 다음은 모두 `ErrUnsupported`다: 다른 `version`이나 `version` 없음, 모르는 키(최상위, 항목, 위치), 키 순서가 다른 것, 주석 줄과 줄 끝 주석, 탭과 다른 들여쓰기, 빈 줄, 줄 끝 공백, 같은 이름 두 번, 빈 `name`, `store`, `file`, 모르는 `action`과 분류, `customer-data` 분류, 앵커, 별칭, 태그, 흐름 표기, `---`와 `...`, 블록 스칼라, 작은따옴표, `\u`로 쓴 대리 문자, UTF-8이 아닌 바이트, BOM, 섞인 줄바꿈, 1MiB를 넘는 입력.
   - 오류 글은 줄 번호와 정해진 사유만 담고 그 줄의 내용은 담지 않는다.
   - 빈 파일(0바이트)은 항목 없는 manifest다.
2. 항목은 placeholder 표기마다 하나이고 이름으로 식별한다(검토 항목 20). 한 묶음이 `.yml`과 `.sh`에 걸치면 `ext.…`와 `EXT_…` 두 항목이 같은 `store`를 가리킨다. 분류는 비밀 값의 네 분류만 쓰고, 고객정보는 넣지 않는다.
3. `Merge`는 새 이름을 "이름이 그보다 뒤인 첫 항목" 앞에 넣는다. 이름순으로 쓴 파일에서는 이름순 자리이고, 사람이 순서를 바꾼 파일에서는 그 순서를 흐트러뜨리지 않는다. 있는 이름은 `category`, `action`, `store`를 새 값으로 바꾸고 위치를 합친다(같은 파일과 줄은 한 번, 파일과 줄 순). 건드리지 않은 항목은 그대로다. 같은 항목을 여러 번 합쳐도 결과가 같다.
4. 이름순, 파일순은 바이트 순서다(`EXT_…`가 `ext.…`보다 앞이다).
5. `Encode`는 `Parse`가 같은 manifest로 다시 읽지 못할 것을 쓰지 않고 `ErrInvalid`로 거부한다: 빈 `name`, `store`, `file`, UTF-8이 아닌 문자열, 모르는 `action`과 분류, `customer-data`, 0보다 작거나 `MaxLine`보다 큰 `line`, 같은 이름 두 번, 1MiB를 넘는 결과. 오류 글은 항목과 위치의 순번, 필드 이름, 정해진 사유만 담고 값은 담지 않는다. `Merge`는 검사하지 않는다.
6. `Entry`에는 값, 미리보기, 지문을 담을 필드가 없다. `TestEncode_HoldsNoValue`가 필드 목록을 고정한다.

## 이유

- 사람이 넣은 주석이나 모르는 키를 조용히 버리고 다시 쓰면 그 내용이 사라진다. 이해하지 못하는 것은 모두 거부하고 적용을 시작하지 않는 편이(조건 바) 안전하다. 거부되면 사람이 고쳐서 다시 점검하면 된다.
- 파일 이름이 키나 항목을 끼워 넣지 못하게 하려면, 따옴표 없이 쓰는 값을 YAML의 어떤 해석으로도 같은 문자열이 되는 좁은 집합으로 두고 나머지는 모두 한 줄의 큰따옴표 문자열로 써야 한다. 쓰는 이스케이프는 모두 YAML 큰따옴표 스칼라의 이스케이프라 다른 YAML 도구로 읽어도 같은 값이다. JSON의 대리 쌍(`\ud83d\ude00`)은 YAML에서 대리 문자 두 개라 쓰지 않는다.
- 계획이 정한 정규식만으로는 `null`, `true`, `123`, `2026-11-20` 같은 값이 다른 YAML 도구에서 문자열이 아닌 값으로 읽힌다. 그래서 그런 값도 따옴표로 쓴다. 이 패키지의 읽기만 놓고 보면 필요 없지만, manifest는 사람과 다른 도구(Secrets Manager 이전)가 읽는 파일이다.
- 엄격한 읽기는 도구가 쓴 파일을 언제나 다시 읽을 수 있을 때만 안전하다. 도구가 읽지 못할 파일을 쓰면 그 뒤의 모든 적용이 그 파일에서 멈춘다. 그래서 `Encode`가 `Parse`와 같은 검사를 하고, 퍼즈 테스트 둘로 확인한다: `FuzzParse`(읽은 것을 다시 쓰고 읽으면 같다), `FuzzEncode`(임의로 만든 manifest는 `Encode`가 거부하거나, `Parse(Encode(m))`이 `m`이다).
- UTF-8이 아닌 문자열은 큰따옴표 스칼라로 바이트 그대로 나타낼 수 없다. U+FFFD로 바꿔 쓰면 원래 이름과 다르고, 그런 바이트만 다른 두 이름이 같은 이름이 된다. 그래서 바꾸지 않고 거부한다.

## 검토한 다른 방법

- `go.yaml.in/yaml`: 어떤 YAML도 읽지만 주석과 키 순서를 지키며 다시 쓰려면 노드 API로 같은 일을 해야 하고, 형식 하나를 위해 의존성이 는다.
- 키 순서를 가리지 않고 읽기: 사람이 순서를 바꾼 파일도 읽을 수 있지만 상태 기계가 커진다. 거부해도 내용을 잃지 않으므로 택하지 않았다.
- 모르는 키를 보존하며 다시 쓰기: 보존할 위치와 들여쓰기 규칙이 생겨 결국 YAML 처리기를 쓰는 것과 같다.
