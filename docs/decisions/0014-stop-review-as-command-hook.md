# 종료 시 규칙 검토를 command hook으로 실행한다

- 날짜: 2026-11-19
- 상태: 대체됨 (0072 참조)

## 배경

작업을 마칠 때 변경분이 `AGENTS.md`를 지키는지 검토 에이전트가 확인한다. 이 검토는 Claude Code의 `agent` 타입 Stop hook으로 실행했고, 언제 승인하고 언제 막는지는 `review-prompt.md`에 글로 적어 두었다.

계획 2를 하위 에이전트로 구현한 세션에서 이 hook은 턴 종료를 76번 막았다. 그중 75번은 "계획이 끝나지 않았다", "하위 에이전트가 아직 실행 중이다"가 사유였고, `AGENTS.md` 위반을 지적한 것은 1번이었다. 확인한 사실은 다음과 같다.

- hook 입력에는 변경분이 아니라 마지막 응답(`last_assistant_message`), 실행 중인 백그라운드 작업(`background_tasks`), 대화 기록 경로가 들어 있다. 검토 에이전트는 이 정보로 "턴을 끝내도 되는가"를 판단했다. 프롬프트에 없는 판단이다.
- 한 번 되돌려 보낸 뒤에는 Security 위반만 다시 막으라는 규칙도 지켜지지 않아, 수 초 간격으로 연속해서 막았다. Claude Code는 연속 8번에서 끊지만 이 횟수는 도구를 한 번 부를 때마다 초기화된다.
- 검토 에이전트의 Bash 호출이 가끔 권한 거부되어 `git diff`를 보지 못한 채 답했다. `agent` hook의 도구 호출이 어떤 권한으로 실행되는지는 문서에 없고, hook 설정으로 도구를 허용하는 방법도 없다.
- `agent` hook은 실험 기능으로 표시되어 있다.

## 결정

종료 시 규칙 검토를 `command` 타입 hook인 `.claude/hooks/stop-review.sh`로 실행한다.

- 검토를 할지 말지와 판정의 의미는 스크립트가 정한다.
  - 실행 중인 백그라운드 작업이 있으면 검토하지 않는다. `stop-verify.sh`도 같은 경우에 `make check`를 실행하지 않는다.
  - Go 소스, `go.mod`, 템플릿, 마이그레이션 파일이 바뀌지 않았으면 검토하지 않는다.
  - 이미 승인한 것과 같은 변경분은 다시 검토하지 않는다. 승인한 변경분의 해시를 `.git/stop-review-approved`에 둔다.
  - 한 번 되돌려 보낸 턴에서는 Security 절 위반만 다시 막는다.
  - 검토기가 실행되지 않거나 판정을 읽을 수 없으면 막지 않고, 사용자에게 보이는 메시지를 남긴다.
- 검토기는 `claude -p`로 띄우는 별도 세션이다. 변경분을 표준 입력으로 받고, 위반 목록만 JSON 스키마에 맞춰 답한다. hook을 끄고(`disableAllHooks`), 읽기 전용 도구(Read, Grep, Glob)만 주며, 모델은 sonnet이다.

## 이유

- 막는 조건을 글로 적어 모델에게 맡기면 지켜지지 않을 수 있다. 셸의 조건문은 항상 같게 동작하고 `hooks_test.sh`로 시험할 수 있다.
- 검토기에 변경분만 주면 턴이나 계획의 완료 여부를 판단할 재료가 없다.
- 변경분을 스크립트가 만들어 넘기므로 검토기는 명령을 실행할 필요가 없고, 권한 거부가 생기지 않는다.
- 백그라운드 작업이 실행 중일 때의 종료는 결과를 기다리는 일시 정지다. 그 작업이 파일을 고치는 중일 수 있어, 이때의 검사 결과는 믿을 수 없다. 작업이 끝나 턴이 다시 종료될 때 검사와 검토가 실행된다.
- 같은 가짜 변경분으로 재 보니 검토 한 번의 비용은 기본 모델에서 약 1.48달러, sonnet과 프로젝트 설정만 읽는 구성에서 약 0.06달러였다. 위반 지적은 같았다.

## 검토한 다른 방법

- `agent` hook을 두고 프롬프트만 고치기: 완료 여부를 판단하지 말라고 적을 수는 있다. 그러나 hook 입력에 판단 재료가 그대로 남고, 권한 거부는 고칠 방법이 없으며, 지켜지는지 시험할 수 없다.
- `prompt` 타입 hook: 한 번의 응답으로 판정하므로 파일을 읽을 수 없고, 입력도 `agent` hook과 같다.
- `claude -p --bare`: hook을 건너뛰지만 API 키가 있어야 하고 로그인한 계정을 쓰지 못한다.
- 종료 시 검토를 없애고 PR 검토에 맡기기: 주석과 기록, 비밀 값의 경로처럼 린터가 보지 못하는 규칙을 작업 중에 잡을 수 없게 된다.
