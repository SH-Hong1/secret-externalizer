# 화면 글꼴: IBM Plex Sans KR과 D2Coding

- 날짜: 2026-11-19
- 상태: 확정

## 배경

화면 시안(`docs/design/`)을 확인받으면서 글꼴을 정했다. 이 도구는 CDN을 쓰지 않고 CSP가 `default-src 'self'`이므로, 웹 글꼴을 쓰려면 파일을 저장소에 넣어 web 바이너리와 함께 내보내야 한다. 화면에는 한글 본문과 함께 코드, 파일 경로, placeholder 이름이 많이 나온다.

## 결정

- 본문, 제목, 버튼은 IBM Plex Sans KR이다. 굵기 400, 600, 700을 넣는다.
- 코드, 파일 경로, placeholder 이름, 커밋 해시, 시각은 네이버 D2Coding이다. 굵기 400, 700을 넣는다.
- 두 글꼴을 woff2 파일로 `internal/web/static/` 아래에 넣고 `@font-face`로 불러온다. 각 글꼴의 라이선스 전문을 글꼴 파일 옆에 둔다.
- 글꼴을 받지 못한 경우의 대체 글꼴은 `system-ui, sans-serif`와 `ui-monospace, monospace`다.

## 이유

- 두 글꼴 모두 SIL Open Font License 1.1이라 저장소에 넣어 다시 배포할 수 있다.
- D2Coding은 한글과 영문의 폭이 2:1로 맞는 고정폭 글꼴이라, 한글 주석이 섞인 주변 코드에서 열이 어긋나지 않는다. `0`과 `O`, `1`과 `l`이 뚜렷이 구분되어 가린 값의 앞 4자를 읽기 쉽다. 사용자가 이 글꼴을 골랐다.
- 본문을 OS 글꼴에 맡기면 macOS와 Windows에서 화면이 다르게 보이고, 리포트 PDF를 만드는 컨테이너(계획 6)에는 한글 글꼴이 없다. 글꼴을 함께 내보내면 세 곳의 모양이 같다.

## 검토한 다른 방법

- **화면 전체를 D2Coding으로**: 글꼴 파일이 하나로 줄지만 본문 문장을 고정폭으로 읽어야 한다.
- **본문은 OS 글꼴, 코드만 D2Coding**: 넣을 파일이 줄지만 OS마다 모양이 다르고 PDF 컨테이너에 한글 글꼴을 따로 넣어야 한다.
- **코드도 IBM Plex Mono**: 시안은 이 글꼴로 그렸다. 한글이 없어 한글 주석이 다른 글꼴로 바뀌면서 열이 어긋난다.
