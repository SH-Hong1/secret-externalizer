# task 하나를 PR 하나로 스쿼시 병합하고, CI가 통과하면 자동으로 병합한다

- 날짜: 2026-11-25
- 상태: 확정

## 배경

요구사항과 task를 GitHub Milestone, Issue, Project로 관리한다. 커밋 메시지는 Angular 형식으로 쓰고(0072), PR이 병합되면 Issue가 자동으로 닫혀야 한다. 지금까지는 병합 방식 셋(병합 커밋, 스쿼시, 리베이스)이 모두 허용되어 있었고 CI가 없었다.

app-surveyor는 비공개 저장소라 GitHub Free에서 브랜치 보호를 쓸 수 없었다. 이 저장소는 공개 저장소라서 Free에서도 브랜치 보호와 필수 체크를 쓸 수 있다.

## 결정

- task 하나에 Issue 하나, 브랜치 하나, PR 하나를 쓴다.
- 병합 방식은 스쿼시만 허용한다. 스쿼시 커밋의 제목은 PR 제목이고, 본문은 PR 본문이다.
- PR 제목은 커밋 제목과 같은 형식(영어, Angular, 72자 이하)이다. 스쿼시 커밋의 제목이 되기 때문이다. PR 본문은 한국어로 쓰고 `Closes #<task 번호>`를 적는다. CI의 `pull-request` 작업이 둘을 확인한다.
- CI는 PR과 `main` push에서 돈다. `check`는 `make check`, `integration`은 compose의 테스트 서비스로 `make test-integration`, `pull-request`는 PR 제목과 본문을 검사한다.
- 병합된 브랜치는 자동으로 지운다. PR을 만들면 `gh pr merge --auto --squash`로 자동 병합을 걸고, 필수 체크가 모두 통과하면 GitHub가 병합한다. 필수 체크와 브랜치 보호는 AI 검토 작업이 들어간 뒤에 켠다(0073).

## 이유

- `main`의 커밋 하나가 task 하나에 맞는다. 이력만 보고도 무엇이 언제 들어갔는지 알 수 있고, 되돌릴 때도 커밋 하나만 되돌리면 된다.
- PR 본문의 `Closes #N`이 스쿼시 커밋에 그대로 들어가서 Issue가 닫힌다.
- PR 제목을 영어로 쓰면 `main`의 이력이 AGENTS.md의 "커밋 메시지는 영어" 규칙을 지키고, 검사 스크립트를 app-surveyor와 함께 쓸 수 있다. 이 스크립트는 72자 제한을 바이트로 세기 때문에 한국어 제목은 대부분 제한을 넘는다.
- 사람이 병합 단추를 누르지 않아도 되고, 검사를 통과하지 못한 변경은 `main`에 들어가지 않는다.

## 검토한 다른 방법

- 병합 커밋: 브랜치의 중간 커밋이 `main`에 모두 남아 이력이 길어진다.
- 리베이스 병합: 중간 커밋마다 형식과 검사 통과를 지켜야 한다. task가 작으면 얻는 것이 없다.
- 한국어 PR 제목 허용: `main`의 이력에 언어가 섞이고, 검사 스크립트가 글자 수를 세도록 고쳐야 한다.
